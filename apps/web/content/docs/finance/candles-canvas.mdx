## Why not Recharts

[`chart-finance-candlestick`](/docs/finance/candlestick) draws candles as custom
Recharts shapes, which is the right call for a fixed window of a few dozen bars.
It has no notion of a viewport, though — there is nothing to pan or zoom, and
every bar is a DOM node whether or not it is on screen.

An exchange chart is the opposite shape of problem: the series is long, the
window moves, and panning is the primary interaction rather than hover. That
needs a renderer, not a series.

## What it does

Everything is drawn by hand onto a 2D canvas — grid, axes, candles, volume, and
the crosshair readouts.

**Only the visible slice is drawn.** The series is 20,000 bars; the window is a
few hundred. Cost tracks the window, not the dataset, so the same code is fine
at 20,000 bars or 200,000.

**Nothing re-renders React.** Pan, zoom and crosshair state live in refs and
draw on the next animation frame. The readouts are painted into the canvas
rather than rendered as DOM, so dragging causes zero React work.

**Zoom is anchored to the cursor.** The bar under the pointer stays put as the
window widens or narrows, which is what makes a wheel zoom feel attached to the
chart rather than to the viewport.

**Axis ticks land on readable values.** Splitting a range into equal parts gives
labels like 41,378.4. The price axis picks from 1 / 2 / 5 and their decades; the
time axis picks from a table of real intervals (1m, 5m, 15m, 1h, 4h, 1d, 1w) so
labels never crowd.

**Bars degrade below 3px.** A body that thin is illegible, so the candle drops
to a single wick line — the shape of the range still reads when the window is
wide.

## Data shape

```ts
type Bar = {
  t: number // epoch ms
  o: number
  h: number
  l: number
  c: number
  v: number
}
```

Bars are assumed evenly spaced by a fixed interval (`BAR_MS`), which is what
lets the x position be an index rather than a scale lookup. Irregular series
need a real time scale instead.

## Not included

Pinch-zoom, indicator overlays, drawing tools, and a live data feed. The last
one is the interesting gap: wiring this to a websocket means appending to the
series, deciding whether the viewport follows the tail, and rolling ticks up
into bars — none of which the renderer itself has an opinion about.

For a chart with indicators and drawing tools out of the box, TradingView's
Lightweight Charts covers that ground and is Apache-2.0. This one exists to own
the rendering path end to end.
